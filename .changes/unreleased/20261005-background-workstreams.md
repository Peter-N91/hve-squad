- **Background workstreams under `routing=economy` (economy-only, interactive mode only; `delivery=background` is ignored under `off`, `ranked`, and `manual`, which keep v0.18.0 behavior).** Under economy, independent workstreams with disjoint write sets run as background subagents under one confirmation while the coordinator keeps talking to the user. Coordinator-only gates run in the foreground first, and only a bounded workstream or one with a confirmed plan launches. A `## Background Workstreams Launched` decision is recorded before launch, and a resumed session uses it to verify and record, or report as not delivered, any workstream that has no hand-off yet. The coordinator dispatches a bounded workstream's owners and named reviewer directly; only a multi-stage workstream uses the new non-user-invocable `Squad Workstream Lead`, which carries the Squad Lead's pin and no `tools:` list, copies each owner's `Model` cell, picks no model, and writes no squad state. Each workstream is verified on disk and handed to the Squad Scribe, which runs `Write-SquadHandoff.ps1`; its per-root lock writes concurrent hand-offs one after the other, and a Tier 0 test starts two at once on one root and checks both land and the ledger check passes. The script accepts an optional `workstream` id (with `launchedAt` and `since`), requires a review-class record for it, refuses a deliverable already credited and not modified since, and records the lead's own turns from `orchestration.leadConsumption`. VS Code has no background `task`, so there the same workstreams run one at a time in the foreground. `Get-SquadDispatchBrief.ps1 -Background` embeds the procedure. The coordinator's only change is the lead in its `agents:` list; the procedure lives in `references/economy-mode.md`.
