- **A fresh squad could loop for minutes during Init, re-dispatching the Scribe and spending tokens without converging.** Two defects compounded. First, `0.18.0` moved the cast catalog out of the auto-applied roster instructions into `references/roster-catalog.md`, which the Scribe never reads, while the Init payload still carried role ids only, so the Init Scribe could compose generic agent names and a reworded `routing.md` that failed the coordinator's roster precheck. The Init and roster-refresh payloads now carry every confirmed `team.md` row in a new `roster` field, resolved by the coordinator; the Scribe copies the cells verbatim and returns a failure note rather than deriving an agent name (`squad-src/.github/skills/squad/references/scribe-payload-template.md`, `squad-src/.github/skills/squad/references/scribe-cold-init-and-seeding.md`, `squad-src/.github/agents/squad/squad-scribe.agent.md`, `squad-src/.github/agents/squad/squad-coordinator.agent.md`).
- **Init contradicted the floor about `history/`, and left the ledger one block behind.** The Init procedure demanded an empty `history/`, while the floor (and `SQ-09`) require the Scribe's own Init orchestration block in `history/Squad Scribe.md`; the Init payload carried no `ledgerCommand`, and the Scribe's Init dispatch table omitted the `consumption.md` template. The coordinator's next `Measure-SquadLedger.ps1 -Check` therefore failed by construction, and each corrective Scribe pass appended another block that a hand-written ledger never folded in. Init now writes no agent file, records its orchestration block, and runs `ledgerCommand` last; roster refresh does the same, and the Scribe reads the ledger template on Init (`squad-src/.github/skills/squad/references/scribe-procedure.md`, `squad-src/.github/skills/squad/references/operating-procedure.md`).
- **Init verification and Ledger Reconciliation are now bounded: repair once, then stop.** A failed check gets one corrective Scribe hand-off carrying `ledgerCommand`; when the re-check still fails, the coordinator reports the failing roles or the `-Check` output to the user instead of dispatching the Scribe again. The Scribe hot core stays within its byte budget, so no Scribe dispatch reads more than before. Pinned by `GATE-38`..`GATE-41` in `tests/tier0/ScribeInitConvergence.Tests.ps1`.
