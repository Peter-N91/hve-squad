- **A fresh squad could loop for minutes during Init, re-dispatching the Scribe and spending tokens without converging.** Two defects compounded. First, `0.18.0` moved the cast catalog out of the auto-applied roster instructions into `references/roster-catalog.md`, which the Scribe never reads, while the Init payload still carried role ids only, so the Init Scribe could compose generic agent names and a reworded `routing.md` that failed the coordinator's roster precheck. The Init and roster-refresh payloads now carry every confirmed `team.md` row in a new `roster` field, resolved by the coordinator; the Scribe copies the cells verbatim and returns a failure note rather than deriving an agent name (`squad-src/.github/skills/squad/references/scribe-payload-template.md`, `squad-src/.github/skills/squad/references/scribe-cold-init-and-seeding.md`, `squad-src/.github/agents/squad/squad-scribe.agent.md`, `squad-src/.github/agents/squad/squad-coordinator.agent.md`).
- **Init contradicted the floor about `history/`, and left the ledger one block behind.** The Init procedure demanded an empty `history/`, while the floor (and `SQ-09`) require the Scribe's own Init orchestration block in `history/Squad Scribe.md`; the Init payload carried no `ledgerCommand`, and the Scribe's Init dispatch table omitted the `consumption.md` template. The coordinator's next `Measure-SquadLedger.ps1 -Check` therefore failed by construction, and each corrective Scribe pass appended another block that a hand-written ledger never folded in. Init now writes no agent file, records its orchestration block, and runs `ledgerCommand` last; roster refresh does the same, and the Scribe reads the ledger template on Init (`squad-src/.github/skills/squad/references/scribe-procedure.md`, `squad-src/.github/skills/squad/references/operating-procedure.md`).
- **A cost-ledger mismatch could stop a run and switch Scribe hand-off pipelining off for the rest of it.** In `0.18.0`, any failed verification of a pipelined hand-off latched pipelining off and held the run at the next barrier until a human approved, even when the only defect was cost accounting the next ledger rewrite would fix. `Measure-SquadLedger.ps1 -Check` now prints a `failure class:` line: `history-integrity` (a history entry missing, removed, overwritten, reordered, or inserted, or a protected deliverable changed) keeps that fail-closed rule; `ledger-only` never disables pipelining, counts as verified for a barrier, and is recorded as a warning while the run continues. Init verification and Ledger Reconciliation get exactly one corrective Scribe hand-off carrying `ledgerCommand`, then warn and continue — never another Scribe pass, never a stop. The Scribe hot core stays within its byte budget, so no Scribe dispatch reads more than before. Pinned by `GATE-38`..`GATE-44` in `tests/tier0/ScribeInitConvergence.Tests.ps1` (`squad-src/.github/skills/squad/scripts/Measure-SquadLedger.ps1`, `squad-src/.github/skills/squad/references/operating-procedure.md`, `squad-src/.github/skills/squad/references/gates-and-modes.md`).
- **A trailing marker comment latched pipelining off on a healthy run.** Every append-only template (`decisions.md`, `history/<agent>.md`, `notifications.md`, federation `decisions.md`) ended with an `<!-- Append each new ... -->` comment, which models read as "write above me". A pipelined Scribe hand-off that did so failed `-Check -BaselinePath` as "inserted inside the file", latching pipelining off although no byte was lost and the entry order was intact. The templates no longer end with a marker, the Scribe appends below any marker an existing file still carries, and the baseline check only warns for that case; an entry inserted above an older entry still fails (`squad-src/.github/skills/squad/references/entry-schemas.md`, `squad-src/.github/skills/squad/references/scribe-procedure.md`, `squad-src/.github/skills/squad/references/scribe-cold-gates-and-verdicts.md`, `squad-src/.github/skills/squad/references/federation-templates.md`, `squad-src/.github/instructions/squad/squad-notifications.instructions.md`).
- **A collapsed code fence turned into an edit to history, which latched pipelining off after the plan stage.** A Scribe that writes a consumption block through a PowerShell double-quoted string collapses its ```` ```json ```` fence to `` `json ``. The ledger refused to read that block, so the next hand-off re-typed the earlier entry with a correct fence, the baseline check saw a rewritten prefix, and the run lost pipelining with no content lost. `Measure-SquadLedger.ps1` now parses a collapsed fence, counts the block, and only warns; `-Check -BaselinePath` only warns when a later write restores such a fence and changes nothing else, while any other rewrite of an earlier entry still fails. The Scribe is told never to re-type an earlier entry, not even to fix its fence, and the coordinator never to ask for a fence repair or a restated block, which would count the same spend twice (`squad-src/.github/skills/squad/scripts/Measure-SquadLedger.ps1`, `squad-src/.github/skills/squad/references/scribe-procedure.md`, `squad-src/.github/skills/squad/references/operating-procedure.md`).
