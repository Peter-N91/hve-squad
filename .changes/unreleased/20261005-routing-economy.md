- **Opt-in `routing=economy` for cheaper implementation picks (applies only under `routing=economy`; `off`, `ranked`, and `manual` are unchanged from v0.18.1).** A new routing mode, persisted as `Model routing: economy` in `team.md`. Its whole procedure lives in the new cold reference `references/economy-mode.md`, read only under economy; `model-routing.md` carries one table row and one sentence pointing to it, and no other hot file grows beyond the mode's name in a list. Switching to economy first tells the user once what changes and records a `## Economy Mode Accepted <timestamp>` decision with fixed `User`, `Previous mode`, `Trade accepted`, and `Never weakened` bullets, written by the Scribe with the roster refresh; `Resolve-SquadModelRoute.ps1` reports `consent: recorded` or `consent: missing` under economy (a warning, never a refusal); every history entry under it carries `Route: economy`. Only an explicit allowlist of roles (`developer`, `technical-writer`, `presenter`, `prompt-engineer`, `data-scientist`) gets the lowest-Blended id at fit 2 or better within its own Model Tier floor; `product-owner`, `deployer`, `iac-author`, `release-engineer`, `backlog-executor`, every review and council role, and every other role keep their `ranked` pick, and no floor or gate is relaxed. After a `Fail` verdict, a Critical or High finding, or a `blocked` owner, that owner is re-dispatched once on its `ranked` pick, which the Scribe writes into the cell first; when the economy pick already is the ranked pick there is no escalation. A Watch Mode trigger's `routing=economy` text is ignored like every other routing input. `scripts/Resolve-SquadModelRoute.ps1 -Mode economy` applies the allowlist and returns the pick, the escalation id, and the agent's pin (now also found in an installed plugin's `agents/` folder). A new Tier 0 test keeps 30 hot files (every file a default, ranked, or manual run reads each turn) within a one-line pointer of v0.18.1.
