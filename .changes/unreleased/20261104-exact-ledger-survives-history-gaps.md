- **The consumption ledger fell back from exact to estimated totals after a gap in the squad history, and stayed there.** `Measure-SquadLedger.ps1 -Write -SessionLog auto` rejected a whole session when one dispatched agent had no history entry (an alternate such as `ADR Creator` re-dispatched to another agent), or when history written after a session's last accepted write predated the next session, and the exact-session journal then stopped advancing. Native usage is now authoritative and the history is bookkeeping: usage by an agent with no history entry keeps its own row, history written after an earlier session's last write is reconciled by re-reading that session's log, a repository session that never reached the journal is adopted when its own log shows a hand-off or squad agent at the entry's time (a plain chat in the same folder never is), and a journal that stopped advancing recovers on the next write with no manual repair. Every remaining gap is a `NOTE:` line in the Derivation (JSON `exact.notes` and `exact.partial`, plus a one-time `WARN:`), and a gap that can only understate labels the exact Cost Comparison a lower bound; nothing is estimated to fill it (`squad-src/.github/skills/squad/scripts/Measure-SquadLedger.ps1`, `squad-src/.github/skills/squad/references/consumption.md`).
- **The wrong session could stand in for the one doing the hand-off.** `SquadUsage.psm1` now prefers the session the host names in `COPILOT_AGENT_SESSION_ID`, and without it the ledger takes the newest log that shows squad work, so a chat written more recently in the same folder, or a second window, cannot be mistaken for the running session. An older cached session that resumes keeps its own snapshot. A partially written last log line is ignored, and `ConvertFrom-Json -DateKind` is used only where PowerShell supports it (`squad-src/.github/skills/squad/scripts/SquadUsage.psm1`).
- **A manual `-Write`, an unreadable log, or a damaged record could replace exact totals with estimates.** A `-Write` without `-SessionLog` on a root that keeps a journal now acts as `auto`; with no readable session log, or a cached session whose log lost records or gained a damaged one, the last accepted totals stay exact as of their snapshot and say so. A usage record with no model is priced under `unknown` without disturbing the baseline model, nano-AIU amounts print the same whether they come from a log or the journal, and a root that falls back to estimates now drops its stale exact Cost Comparison. The estimator remains only where no native usage can be trusted: none at all, incomplete or non-reconciling credit records, history-prefix drift, or a journal this version rejects. A journal that is not even a JSON object (cut short, emptied by a crash, merge markers) no longer pins the ledger to estimates: a write rebuilds it from the native logs and keeps its bytes as `consumption-sessions.json.unreadable-<digest>`.
- **A resumed or concurrent session could hide a session that never reached the journal, and a lower bound was not always labelled.** When the running session was already journaled, was opened before the missing one, worked within minutes of it, or the sessions handed off in a different order than they were opened, a session whose hand-off never reached the ledger stayed out of the totals with no note. Each uncovered history entry now goes to the session whose own log shows it most convincingly (a shell call that runs a history writer for this squad root just before the stamp outranks squad usage billed nearby; a view, a search, a ledger check, or another root's hand-off is no evidence at all, and a session that was handing off for another root at that moment earns no usage credit for the entry), every session that shows an entry better than the running one joins the journal, in the order in which it first did so, an accepted session opened one folder below the repository keeps being refreshed (it is found by id, under the session-state root only), and a metered history entry with no billed native request within five minutes in any accepted session is a `NOTE:` that labels the exact Cost Comparison and Unit Economics a lower bound. A session that wrote part of the history but whose usage cannot be attributed is a `NOTE:` too, and no longer stops the others from being added. A write refuses, changing nothing, when another writer changed the journal while it ran, and an unforeseen failure while reconciling the logs keeps the accepted exact totals, labelled, instead of estimating. A request that a forked session's log repeats is counted once, and a host-supplied agent name with a pipe, a line break, a backtick, a leading `#`, or the bare word `Total` prints as plain text that cannot break the tables or `-Check` (`squad-src/.github/skills/squad/scripts/Measure-SquadLedger.ps1`, `squad-src/.github/skills/squad/scripts/SquadUsage.psm1`).
