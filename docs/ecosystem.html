Ecosystem

This repository owns the Copilot plugin and APM fallback. The MCP and MAF repositories carry the same squad model into their respective host runtimes.

The plugin and related repositories

Repository What it is Documentation
hve-squad This repository. It owns the authored squad source, the APM fallback, and the generated stable and preview plugin branches. peter-n91.github.io/hve-squad
hve-squad-mcp An outbound Model Context Protocol server that publishes the squad as model-invocable tools, so MCP hosts can call it. peter-n91.github.io/hve-squad-mcp
hve-squad-maf The Microsoft Agent Framework host for running the squad through MAF. Repository documentation

One cast, multiple hosts. The roster, routing tables, and gates are authored once here. The plugin bundles the exact HVE Core commit pinned by its source release. The MCP and MAF repositories remain separate host integrations rather than plugin dependencies.

hve-squad-mcp — the MCP server

github.com/Peter-N91/hve-squad-mcp · docs site

The server exposes coarse, model-invocable tools that map onto the squad's routing intents rather than onto individual agents: squad_research, squad_plan, squad_review, squad_architect, squad_run, and squad_federate, plus a deterministic squad_render_pptx file-output tool. Every tool's input mirrors the /squad prompt arguments.

It runs in two modes, at different maturity levels:

  • Delegated (stdio) — VS Code dispatches the real deployed cast, so it behaves as the full package. Requires the cast to be installed.
  • Embedded (remote Streamable HTTP + Entra) — reaches hosts such as Copilot Studio, resolving personas server-side from the bundled cast under auth, gates, tenant isolation, and cost caps. Scope is advisory: finished text deliverables, not code-executing implement or deploy.

Read the status table first. The server's README and docs site are explicit about what works today versus what is a deferred execution expansion. Take claims about the remote surface from there rather than from this page.

Useful entry points on its site: Getting Started, Tools, Configuration, and Deploy.

hve-squad — the Copilot plugin

The plugin is generated from this repository by scripts/Build-SquadPlugin.ps1. Manual publication writes stable output to the plugin branch and test output to plugin-preview. Each branch contains one marketplace entry and one plugin. 

copilot plugin marketplace add Peter-N91/hve-squad#plugin
copilot plugin install hve-squad@hve-squad

HVE Core is bundled, not discovered beside the plugin. The generated tree copies every component declared by the exact HVE Core commit pinned in apm.yml and records that commit in .github/plugin/hve-core-source.json. A normal plugin update therefore refreshes Squad and HVE Core together. Do not install a second hve-core plugin.

The plugin has no mcp.json or .mcp.json. Install hve-squad-mcp separately only when an MCP host needs the outbound tools. Stable, preview, update, and fallback instructions live in Getting Started.

How releases stay aligned

Plugin publication remains manual. The workflow selects an immutable stable or rolling preview ref, checks out the HVE Core commit pinned by that ref, builds the self-contained plugin, and updates the matching branch in this repository. A content change without a plugin-version change is rejected so installed clients can detect updates. MCP and MAF keep their own release processes. See Maintaining.
