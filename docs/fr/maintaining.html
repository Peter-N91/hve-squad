Guide mainteneur

Maintenir le package

Travaillez sur les sources, vérifiez les agents réellement disponibles et publiez depuis une référence reproductible.

Structure du dépôt

CheminResponsabilité
apm.ymlMétadonnées, dépendances et scripts du package.
apm.lock.yamlRéférences résolues par APM.
squad-src/.github/Sources des agents, prompts, instructions et skills de la squad.
scripts/Update-ApmDependencies.ps1Générateur de dépendances.
scripts/Get-HveCoreCastDelta.ps1Comparaison des agents déployables entre références HVE Core.
.changes/unreleased/Fragments en attente d'une publication.
apm_modules/ et .github/Dépendances et ressources déployées ; ne pas les confondre avec les sources.
.copilot-tracking/État de travail local ; certaines traces Watch Mode sont suivies pour l'audit.
docs/Documentation statique publiée sur GitHub Pages.

Cycle local

apm run sync-deps
apm install
apm lock

install-sync combine génération et installation. apm pack est facultatif pour produire un artefact, notamment pour le plugin. apm run change prépare un fragment. release-prep assemble une publication ; ne le lancez pas comme simple étape de développement.

Le générateur parcourt les agents, instructions, prompts et skills de HVE Core à la référence choisie, filtre les ressources Markdown et réécrit dependencies.apm. Par défaut, il conserve le SHA déjà épinglé.

Mettre HVE Core à jour

Les rôles désignent les agents par leur nom exact. Avant de changer le SHA, vérifiez si un agent référencé a disparu, changé de nom ou perdu sa capacité de délégation :

./scripts/Get-HveCoreCastDelta.ps1
./scripts/Get-HveCoreCastDelta.ps1 -ToRef main -MarkdownPath delta.md

Évolution mécanique

Sans changement bloquant du catalogue, la synchronisation déplace le pin et ajoute un fragment. Elle ne publie pas automatiquement une version stable. La modification attend la prochaine publication décidée par un mainteneur.

Adaptation du catalogue

En cas de rupture, la synchronisation ne modifie pas le manifeste : elle crée une issue squad/auto avec le diagnostic et les critères d'acceptation. Watch Mode travaille dans issue-<N> et ouvre une PR en brouillon. Le label squad/review déclenche une revue distincte sous pr-<N>.

Examinez les nouvelles correspondances de rôles et l'historique de chaque délégation. Un agent marqué disable-model-invocation: true ne peut pas remplir un rôle délégué. Un historique vide ne prouve pas que les spécialistes ont réellement travaillé.

Exécution sans utilisateur

Les transitions reposent sur les preuves. Les conclusions et risques sont portés dans la PR en brouillon ; ils ne deviennent pas une approbation humaine. Aucune fusion, aucun déploiement, force-push, changement de données, rotation de secret ou écriture dans un backlog externe n'est autorisé par ce mode.

Configurez les secrets COPILOT_GITHUB_TOKEN et SYNC_DEPS_TOKEN selon les workflows, les labels, les droits de création de PR et la protection de branche. Épinglez le modèle CLI via --model ou le paramètre prévu par le workflow ; le frontmatter d'un agent ne suffit pas à fixer le modèle d'un run sans interface.

Sources et références reproductibles

Modifiez squad-src/.github/agents/squad/, instructions/squad/, prompts/squad/ ou skills/squad/ sous cette même racine. APM aplatit le contenu vers .github/ lors du déploiement : modifier cette sortie exposerait vos changements à un écrasement.

SquadSourceRoot, SquadRepoSlug et SquadRef contrôlent les auto-références de la squad. RepoSlug, Ref, IncludeRoots et IncludeRegex contrôlent la découverte HVE Core. Utilisez -DryRun pour inspecter le résultat sans écrire.

Depuis v0.15.2, le workflow de publication épingle les auto-références avec Set-SquadSelfRefPin.ps1 dans un commit propre au tag ; main garde ses références de développement. Les anciens tags ne garantissent pas cette reproductibilité. Vérifiez une installation depuis un clone frais du tag, pas seulement depuis l'arbre de travail.

Contrats et tests

Lors d'une évolution du plafond de coût, gardez synchronisés les paramètres des prompts, references/consumption.md, gates-and-modes.md, les schémas d'entrée, les modèles de fédération, la procédure du Scribe et les coordinateurs. L'initialisation reste hors plafond et seul l'autopilot de fédération non ciblé porte un contrôle agrégé.

./tests/tier0/Invoke-Tier0Tests.ps1 -SourceRoot .
./tests/tier1/Invoke-Tier1Tests.ps1 -SelfCheck -Output Normal
git diff --check

Les tests déterministes ne prouvent pas les résultats d'une exécution avec modèles. Les runs live constituent une vérification séparée et consomment des requêtes Copilot.

Documentation bilingue

Le site reste en HTML statique. Les pages anglaises sont dans docs/ et leurs correspondantes françaises dans docs/fr/, avec les mêmes noms de fichiers. Les styles et contrôles communs sont dans docs/assets/style.css, theme.js et site.js.

Mettez à jour les deux langues dans la même PR, conservez les identifiants d'ancre et les commandes, puis testez les onglets, la navigation mobile et les liens de langue. Les rapports historiques et vidéos gardent leur langue d'origine, explicitement indiquée. Les pages restent lisibles sans JavaScript.

npm --prefix tests/docs ci --ignore-scripts
  npm --prefix tests/docs test

Ouvrez docs/index.html directement dans le navigateur. Aucun serveur ni build React n'est requis. Le workflow .github/workflows/docs.yml publie le dossier docs sur GitHub Pages.

Fragments et publications

Une PR ajoute un nouveau fragment dans .changes/unreleased/, sans modifier CHANGELOG.md ni version: dans apm.yml. Le niveau suit les concepts : une extension ordinaire est généralement un patch, une nouvelle idée un minor, une rupture consommateur un major.

La validation de PR contrôle les fragments et les déplacements de pin non autorisés. Une fusion alimente la préversion glissante ; elle ne publie pas une version stable. Un mainteneur déclenche Release Prep quand le lot est prêt. Le workflow assemble le changelog, calcule la version, consomme les fragments et lance la publication du tag.

Un correctif isolé doit partir d'une branche issue du dernier tag si main contient du travail non publiable. Sélectionner des fragments ne sélectionne pas le code livré. Voir Contribuer et la référence détaillée de maintenance en anglais pour les options avancées des workflows.
