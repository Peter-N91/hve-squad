Dépannage

Identifiez l'environnement utilisé, l'étape en échec et les preuves disponibles avant de relancer le travail.

Plugins et agents

Le coordinateur est introuvable dans CLI ou App

Vérifiez que hve-squad et hve-squad-hve-core sont tous deux installés dans le client courant. L'application peut utiliser un autre COPILOT_HOME. Dans CLI, saisissez /agent et cherchez Squad Coordinator ou hve-squad:squad-coordinator.

/squad charge du texte mais ne lance pas l'équipe

Vous avez probablement sélectionné le skill. Dans VS Code, choisissez le prompt « Hands a request to the Squad Coordinator… ». Dans CLI ou App, sélectionnez directement l'agent coordinateur, puis envoyez les arguments sans préfixe.

Un spécialiste manque ou ne produit aucun livrable

Demandez squad-doctor. La distribution plugin peut manquer de domaines HVE Core ; le remède documenté est apm install github/microsoft/hve-core --target copilot dans le dépôt. Ne remplacez pas silencieusement le spécialiste par un autre agent.

Vérifiez le Primary du rôle dans .copilot-tracking/squad/team.md, sa disponibilité et son dossier de livrables. Un agent délégué peut aussi refuser une demande faute de contrat d'entrée complet. Après une évolution HVE Core, les mainteneurs peuvent comparer les agents avec scripts/Get-HveCoreCastDelta.ps1.

Le compagnon affiche already at latest

La version propre à HVE Core peut rester identique alors que le SHA du marketplace a changé. Désinstallez puis réinstallez hve-squad-hve-core dans chaque environnement concerné. Ne cumulez pas ce compagnon avec le plugin officiel hve-core. Voir les commandes de mise à jour.

Installation APM

L'installation dépasse 30 minutes sans erreur

La cause habituelle est la limite GitHub de 60 requêtes par heure sans authentification. APM attend la réinitialisation de la fenêtre. Authentifiez-vous, puis relancez :

gh auth login
apm install "Peter-N91/hve-squad#vX.Y.z" --target copilot

Remplacez le tag par une version publiée. Le cache évite de retélécharger les fichiers déjà présents. Augmenter le parallélisme ne supprime pas la limite horaire.

L'ordre de recherche du jeton APM est GITHUB_APM_PAT_<ORG>, GITHUB_APM_PAT, GITHUB_TOKEN, GH_TOKEN, gh auth token, puis l'assistant d'identifiants Git. Vérifiez votre configuration sans afficher de secret dans une conversation ou un journal partagé.

Quelques téléchargements échouent avec HTTP 502 ou 503

Il s'agit généralement d'un incident temporaire côté GitHub, pas d'un changement de pin. Relancez apm install --target copilot ; les fichiers en cache sont conservés. Si les erreurs persistent, consultez GitHub Status. Une erreur 404 indique plutôt un fichier absent à la référence demandée.

No harness detected ou dossier .github/ vide

Depuis APM 0.18.0, un projet sans marqueur d'environnement n'est plus déployé implicitement vers Copilot. Les sources peuvent déjà être présentes dans apm_modules/. Relancez avec --target copilot ou ajoutez targets: [copilot] dans apm.yml. Voir Bien démarrer.

Scripts absents, accès refusé ou dépendances anciennes

apm list affiche les scripts déclarés. Vérifiez l'authentification Git et l'accès au dépôt. En tant qu'utilisateur, réinstallez la version souhaitée. En tant que mainteneur du package, régénérez les dépendances avec apm run sync-deps, puis apm lock.

Plafond de coût estimé

L'initialisation précède le contrôle du plafond

C'est prévu : elle crée les fichiers nécessaires au calcul et reste hors plafond. Sa consommation estimée est néanmoins enregistrée. Le contrôle précède la première unité de travail après cette configuration.

Le run s'arrête avec over-ceiling

Il s'agit d'une prévision, pas d'une preuve de facturation. Ouvrez la Decision Ref vers decisions.md, puis examinez consumption.md et consumption-rates.md. Le contrôle applique une réserve de 3 à l'estimation restante.

Si le cumul reste sous le plafond et la prévision est suffisamment fondée, vous pouvez approuver une poursuite séquentielle bornée. Avec cannot-confirm, corrigez d'abord les données manquantes ; l'approbation ne peut pas les remplacer.

Une nouvelle demande garde l'ancien plafond

Dans le même run, l'omission signifie héritage. Remplacez la valeur ou retirez-la explicitement :

/squad request="Continue sans plafond de coût" cost-ceiling=unset

Dans CLI ou App, envoyez les arguments au coordinateur sans /squad. Un nouveau run sans plafond fourni démarre avec not-requested.

Le dernier appel a dépassé la limite

Un appel en cours ne peut pas être interrompu par ce contrôle. Le Scribe enregistre son coût, puis aucune unité suivante ne démarre. Relevez la limite au-dessus du cumul, retirez-la, réduisez le travail ou démarrez un nouveau run. Un plafond de 10 USD avec 10,80 USD déjà estimés laisse zéro budget disponible.

Chaque sous-squad reçoit le plafond

C'est le comportement normal du routage ciblé ou ordinaire : le plafond s'applique séparément à chaque sous-squad. Seul l'autopilot de fédération sans squad= utilise un plafond agrégé à la racine. Voir le contrat de coût.

Diagrammes et fichiers suivis

Les diagrammes Azure avec icônes ne se génèrent pas

Le rendu optionnel repose sur Python, la bibliothèque diagrams et le binaire Graphviz dot. Si python lance le raccourci Microsoft Store, utilisez uv :

uv run --with diagrams python docs/architecture/your-diagram.py
dot -V

Si Graphviz manque, installez-le avec la procédure autorisée sur votre poste puis rouvrez le terminal. Sans cet outillage, utilisez Mermaid. Le contrôle fourni par le skill est uv run --with diagrams python .github/skills/python-diagrams/scripts/verify_installation.py.

.github/ apparaît encore après ajout au fichier d'exclusion Git

Un fichier déjà suivi n'est pas retiré de l'index par .gitignore. Examinez d'abord les chemins suivis. Ne retirez de l'index que les ressources générées concernées et conservez vos workflows ; une suppression globale peut désindexer des fichiers écrits à la main.

Versions et état local

Épinglez un tag publié pour un usage reproductible. La préversion glissante change à chaque fusion et ne remplace pas une version stable. Le journal des versions (anglais) décrit les changements.

apm_modules/ et les ressources générées sont exclus selon les règles du dépôt ; les workflows restent suivis. L'état de la squad est distinct du package. Une réinstallation n'est pas une raison de supprimer vos décisions ou votre historique.
