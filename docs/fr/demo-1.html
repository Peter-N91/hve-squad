Démonstration 01

Squad Azure

Concevoir, chiffrer, préparer et examiner une infrastructure. Les déploiements attendent votre accord ; le diagnostic reste en lecture seule.

Toutes les démonstrations · Migration · Produit · .NET

Avant de commencer

Installez une version publiée de hve-squad, vérifiez les agents du profil azure et authentifiez Azure CLI avec az login. Contrôlez l'abonnement avec az account show. Utilisez un groupe de ressources existant autorisé pour les étapes de documentation et de diagnostic.

Le serveur @azure/mcp est facultatif : les capacités concernées peuvent utiliser Azure CLI et REST en repli. Son installation n'est pas implicitement déclenchée par l'installation du package.

Diagrammes avec icônes Azure

Mermaid convient sans outillage supplémentaire. Pour produire des images PNG/SVG avec le skill python-diagrams, prévoyez Python ou uv et Graphviz. Vérifiez dot -V avant la session. En l'absence de ces outils, conservez Mermaid.

0. Initialiser

/squad init profile=azure

Confirmez l'équipe proposée. Dans CLI ou App, sélectionnez Squad Coordinator et envoyez init profile=azure. Les demandes suivantes s'envoient au même agent, sans le préfixe /squad.

1. Estimer le coût

/squad request="Estime le coût mensuel Azure d'une petite application interne en West Europe : frontend et backend App Service, Azure SQL, Key Vault et Storage, avec réseau privé. L'objectif est moins de 60 USD par mois. Donne une estimation indicative et les compromis nécessaires, sans promettre que cette architecture respecte ce budget."

Examinez les hypothèses de dimensionnement, région, disponibilité et réseau. Le budget est une contrainte à tester, pas un coût garanti. Le plafond de consommation des modèles est un mécanisme distinct.

2. Concevoir puis préparer l'IaC

/squad request="Conçois le HLD et le LLD de cette application avec Azure Verified Modules et une organisation compatible avec une landing zone. Définis VNet, sous-réseaux et endpoints privés nécessaires. Justifie les choix de sécurité et l'intérêt éventuel des conteneurs. Ne déploie rien."
/squad request="Écris le Bicep de ce LLD sous infra/bicep/demo avec des modules AVM. Ne déploie rien."

La recherche et la planification précèdent l'implémentation. Vérifiez la traçabilité entre le LLD et les fichiers IaC ; ne prenez pas une génération de fichiers pour une preuve de compilation.

3. Revoir et préparer le déploiement

/squad request="Revois le Bicep par rapport au LLD. Vérifie la compilation et signale les écarts."
/squad request="Prépare le déploiement de infra/bicep/demo. Exécute le contrôle Azure Policy en lecture seule et présente le what-if ainsi que les contraintes. Attends mon approbation avant toute modification Azure."

Le Deployer présente les politiques effectives et les refus anticipés, puis attend la validation requise. Pour une démonstration sans création de ressources, arrêtez-vous ici ou refusez le déploiement.

4. Documenter l'existant

/squad request="Documente l'infrastructure déjà déployée dans rg-demo : inventaire, matrice de conformité Azure Policy, guide d'exploitation et plan de sauvegarde et reprise. Lecture seule, aucune modification."

Remplacez rg-demo par un groupe autorisé. Le rôle As-Built collecte les preuves et prépare les documents sans déployer.

5. Diagnostiquer un symptôme réel

/squad request="Analyse les erreurs 5xx de l'App Service dans rg-demo. Consulte Resource Health et les journaux récents, classe les causes plausibles et recommande des corrections. Ne modifie rien."

Une recommandation n'autorise pas son application. Le diagnostic nécessite un symptôme réel ; n'inventez pas un incident pour compléter le scénario.

Variante autopilot

Après l'initialisation confirmée, formulez l'objectif complet :

/squad profile=azure mode=autopilot request="Prépare une petite application interne sur Azure en West Europe avec frontend, backend, base SQL, secrets et stockage. Étudie le réseau privé, la sécurité, les contraintes de gouvernance et un objectif de coût mensuel inférieur à 60 USD. Produis l'architecture, l'IaC et sa revue, puis prépare l'exploitation. Signale les compromis ou contraintes incompatibles. Garde-moi décisionnaire pour tout coût cloud et toute modification de l'abonnement."

Attendez des preuves de recherche, planification, revue et validation, pas seulement un résumé confiant. Sans abonnement disponible, restez sur les livrables locaux. Sans outillage de prix avancé, explicitez les limites de l'estimation.
