Guide utilisateur

Bien démarrer

Installez hve-squad dans votre environnement Copilot, choisissez le coordinateur et envoyez votre première demande.

1. Installer dans votre environnement

Copilot CLI

Installez GitHub Copilot CLI, connectez-vous avec un compte disposant d'un accès Copilot et ouvrez un terminal à la racine de votre projet. Installez les deux entrées du marketplace :

copilot plugin marketplace add Peter-N91/hve-squad-plugin
copilot plugin install hve-squad@hve-squad-plugin
copilot plugin install hve-squad-hve-core@hve-squad-plugin
copilot

Dans le sélecteur d'agents, Squad Coordinator peut apparaître sous le nom hve-squad:squad-coordinator. Passez à l'initialisation ci-dessous après avoir vérifié l'installation.

Vérifier les agents disponibles

Demandez au coordinateur d'exécuter squad-doctor avant le travail. Certains domaines HVE Core peuvent manquer dans la distribution plugin. Si le diagnostic le signale, installez le package complet dans le dépôt :

apm install github/microsoft/hve-core --target copilot

Ne cumulez pas le plugin officiel hve-core et hve-squad-hve-core : le routage pourrait choisir une copie non épinglée.

Mettre les plugins à jour

copilot plugin marketplace update Peter-N91/hve-squad-plugin
copilot plugin update hve-squad@hve-squad-plugin
copilot plugin uninstall hve-squad-hve-core@hve-squad-plugin
copilot plugin install hve-squad-hve-core@hve-squad-plugin

Le plugin compagnon doit être désinstallé puis réinstallé : une simple mise à jour peut afficher already at latest alors que son commit épinglé a changé. Consultez le guide CLI du plugin (anglais).

Copilot App

Ouvrez votre projet dans l'application de bureau GitHub Copilot et connectez-vous. Dans les paramètres des plugins, ajoutez le marketplace Peter-N91/hve-squad-plugin, puis installez les deux entrées : hve-squad et hve-squad-hve-core.

Les libellés et l'emplacement des paramètres dépendent de la version. Le guide d'installation de l'application (anglais) décrit le chemin actuel.

Vérifiez l'installation dans l'application. Elle peut utiliser un autre COPILOT_HOME que votre terminal. Une installation ou une mise à jour en ligne de commande ne prouve pas que l'application utilise les mêmes fichiers.

Vérifiez la présence de l'agent Squad Coordinator, éventuellement nommé hve-squad:squad-coordinator, et non du skill du même nom. Demandez squad-doctor et résolvez les agents manquants avant le travail ; la documentation du plugin (anglais) indique les limites et le recours au package APM complet.

Ne cumulez pas le plugin officiel hve-core avec le compagnon. Mettez les deux entrées à jour dans l'environnement de l'application et réinstallez hve-squad-hve-core lorsque son commit épinglé change.

VS Code

Ouvrez votre projet dans VS Code avec GitHub Copilot Chat activé et authentifié. APM installe les agents, prompts, instructions et skills dans le dossier .github/ du projet.

Prérequis

  • PowerShell 7 ou version ultérieure sous Windows, ou un shell zsh/bash récent sous macOS.
  • Git.
  • APM CLI 0.29.0 installé et accessible dans PATH.
  • Accès au dépôt public microsoft/hve-core.
  • Authentification GitHub, de préférence avec gh auth login.

APM CLI 0.29.0 est obligatoire pour l'installation APM. Il s'agit de la dernière version connue qui installe correctement toutes les dépendances HVE Squad. Une régression dans APM 0.29.1 et 0.30.0 provoque l'échec des mêmes 11 dépendances. La version d'APM et celle du package HVE Squad sont deux épingles distinctes : apm --version doit afficher 0.29.0, tandis que #vX.Y.z choisit la version de HVE Squad.

Installer APM CLI 0.29.0

Windows (PowerShell)

$env:VERSION = 'v0.29.0'; irm https://aka.ms/apm-windows | iex
apm --version  # doit afficher 0.29.0

Si la version reste incorrecte, ouvrez une nouvelle fenêtre PowerShell et vérifiez à nouveau. Get-Command apm -All permet d'identifier un ancien exécutable placé plus tôt dans le PATH.

macOS (Apple Silicon ou Intel)

# À exécuter uniquement si Homebrew gère déjà apm ; l'installateur épinglé ne peut pas l'écraser.
brew uninstall apm

curl -sSL https://aka.ms/apm-unix | sh -s -- @v0.29.0

# L'installateur utilise ~/.local/bin. Ajoutez cette ligne à ~/.zshrc pour la conserver.
export PATH="$HOME/.local/bin:$PATH"
hash -r
apm --version  # doit afficher 0.29.0

Si vous préférez une installation isolée sans modifier la copie gérée par Homebrew, utilisez uv tool install apm-cli@0.29.0. Corrigez toute ambiguïté de PATH avant de continuer.

Installer le package

Exécutez ces commandes à la racine de votre projet. Remplacez vX.Y.z par un tag publié sur la page Releases.

gh auth login
apm install "Peter-N91/hve-squad#vX.Y.z" --target copilot

Sans authentification, la limite GitHub de 60 requêtes par heure peut rendre l'installation très lente. L'authentification augmente généralement cette limite à 5 000 requêtes par heure. N'insérez pas vos jetons dans les conversations.

APM 0.18.0 et versions ultérieures : sans environnement détecté, l'installation peut télécharger les sources dans apm_modules/ puis s'arrêter avec No harness detected. Utilisez --target copilot ou déclarez la cible dans le fichier du projet :

name: my-project
version: 0.1.0
targets:
  - copilot

Avec ce bloc dans apm.yml, les installations suivantes n'ont plus besoin de l'option de cible. Relancez apm install après un échec pour déployer les sources déjà téléchargées. Les scripts sync-deps et install-sync sont réservés aux mainteneurs.

Mettre à jour

apm install "Peter-N91/hve-squad#vX.Y.z" --target copilot

Choisissez le nouveau tag publié. La préversion glissante vX.Y.z-pre sert aux essais : elle change à chaque fusion. Sans référence, APM suit la branche par défaut, pas nécessairement la dernière version stable.

L'installation renouvelle les ressources dans .github/, pas votre équipe ni vos décisions dans .copilot-tracking/squad/.

2. Initialiser la squad

Le coordinateur examine votre dépôt et propose un profil. Confirmez les rôles avant la création des fichiers d'état. L'initialisation et la promotion restent interactives.

/squad init

3. Envoyer une demande

/squad request="Ajoute une validation des champs au formulaire de connexion" mode="autopilot"

Omettez mode pour approuver chaque étape. Autopilot enchaîne le travail sans élargir le périmètre et conserve les validations humaines obligatoires.

Dans VS Code, choisissez le prompt « Hands a request to the Squad Coordinator… », pas le skill « Operating procedure for… ». Dans CLI et App, les demandes sont envoyées dans la conversation de l'agent sélectionné.

Limiter le coût estimé

Ajoutez cost-ceiling=10 pour fixer un plafond de 10 USD sur le coût estimé des modèles du run. Il ne garantit pas le montant facturé par GitHub et ne limite pas les ressources Azure. L'initialisation confirmée est hors plafond ; le contrôle s'applique avant le travail qui suit.

Dans un même run, omettre le paramètre conserve le plafond. cost-ceiling=unset le retire explicitement. Le contrôle se fait entre les unités de travail, donc un appel déjà lancé peut dépasser le plafond. Voir le contrôle des coûts.

Préparer une exécution Azure

Avec le profil azure, demandez la préparation du conteneur de développement, des workflows OIDC Bicep ou Terraform, du référentiel de gouvernance et des dossiers infra/. Examinez les fichiers avant de les valider dans Git. Aucun déploiement n'est autorisé par cette seule préparation.

La configuration OIDC initiale nécessite les droits Azure appropriés, notamment Owner ou User Access Administrator pour les affectations RBAC. Les déploiements restent soumis à votre approbation.
