Écosystème

La squad est distribuée via trois dépôts. Celui-ci est la source de référence ; les deux autres sont des modes de distribution qui rendent le même ensemble d'agents accessible aux hôtes qu'une installation APM ne peut pas atteindre.

Les trois dépôts

Dépôt Description Documentation
hve-squad Ce dépôt. Le package APM et les sources de la squad (squad-src/) à partir desquels les deux autres dépôts sont construits. peter-n91.github.io/hve-squad
hve-squad-mcp Un serveur Model Context Protocol sortant qui expose la squad sous forme d'outils invocables par un modèle, pour permettre aux hôtes MCP de l'appeler. peter-n91.github.io/hve-squad-mcp
hve-squad-plugin Un miroir généré de l'arborescence du plugin GitHub Copilot CLI de la squad, publié uniquement lors des sorties de versions, sous forme de marketplace de plugins. peter-n91.github.io/hve-squad-plugin

Une équipe d'agents, trois portes d'entrée. La composition de l'équipe, les tables de routage et les contrôles sont définis une seule fois ici. Le serveur MCP et le plugin ne dérivent pas ce comportement dans des forks — chacun est construit à partir d'une version étiquetée de hve-squad, de sorte qu'une version donnée de chaque mode de distribution correspond à une version connue de ce package.

Quel mode de distribution choisir ?

hve-squad-mcp — le serveur MCP

github.com/Peter-N91/hve-squad-mcp · site de documentation

Le serveur expose des outils de haut niveau invocables par un modèle, qui correspondent aux intentions de routage de la squad plutôt qu'aux agents individuels : squad_research, squad_plan, squad_review, squad_architect, squad_run et squad_federate, ainsi qu'un outil déterministe de production de fichiers squad_render_pptx. Les entrées de chaque outil reprennent les arguments du prompt /squad.

Il fonctionne selon deux modes, à des niveaux de maturité différents :

  • Délégué (stdio) — VS Code délègue aux véritables agents déployés, ce qui reproduit le comportement du package complet. Leur installation est nécessaire.
  • Embarqué (Streamable HTTP distant + Entra) — accessible à des hôtes tels que Copilot Studio, ce mode résout les personas côté serveur à partir des agents inclus, avec authentification, contrôles, isolation des locataires et plafonds de coût. Le périmètre est consultatif : des livrables textuels finalisés, et non de l'implémentation ou du déploiement exécutant du code.

Lisez d'abord le tableau d'état. Le README et le site de documentation du serveur indiquent explicitement ce qui fonctionne aujourd'hui et les extensions d'exécution reportées. Fondez-vous sur ces sources, plutôt que sur cette page, pour connaître les capacités du mode distant.

Points d'entrée utiles sur son site : Bien démarrer, Outils, Configuration et Déploiement.

hve-squad-plugin — le plugin Copilot CLI

github.com/Peter-N91/hve-squad-plugin · site de documentation

Ce dépôt contient du contenu généré, jamais modifié à la main. Ses dossiers agents/, skills/ et son fichier .github/plugin/plugin.json sont régénérés par scripts/Build-SquadPlugin.ps1 uniquement lorsqu'une version de ce dépôt est publiée, par extraction du tag Git immuable de cette version. Il permet de conserver l'arborescence de distribution hors de cette arborescence de travail, sur le modèle du dépôt compagnon hve-squad-mcp.

Le marketplace publie deux entrées à installer ensemble :

copilot plugin marketplace add Peter-N91/hve-squad-plugin
copilot plugin install hve-squad@hve-squad-plugin
copilot plugin install hve-squad-hve-core@hve-squad-plugin

Deux règles régissent toutes les mises à jour ultérieures. hve-squad-hve-core doit être désinstallé puis réinstallé plutôt que mis à jour — copilot plugin update compare la version propre à hve-core en amont : si la référence épinglée change, la commande indique already at latest et les fichiers restent inchangés. N'installez pas également le plugin officiel hve-core à côté, sinon une délégation pourrait aboutir à une seconde copie non épinglée de chaque agent hve-core. Ces deux règles sont expliquées en détail dans Installation : Copilot CLI.

Points d'entrée utiles sur son site : Installation : Copilot CLI, Installation : application de bureau, Installation : notes VS Code, Architecture et Distribution en entreprise.

Comment les versions restent alignées

Aucun des deux dépôts compagnons n'est un fork. Tous deux sont produits à partir d'une version étiquetée de hve-squad et chacun consigne le tag utilisé pour sa construction — le dépôt du plugin indique son tag source et sa date d'extraction dans son README, et chaque version MCP est épinglée à une version correspondante du package. Lorsqu'une version est publiée dans ce dépôt, les modes de distribution en aval sont régénérés à partir de celle-ci, plutôt que d'évoluer séparément selon leur propre calendrier. Consultez Maintenance pour le processus de publication de ce côté.
