Écosystème

Ce dépôt contient le plugin Copilot et la solution de repli APM. Les dépôts MCP et MAF transportent le même modèle de squad dans leurs hôtes respectifs.

Une équipe d'agents, plusieurs hôtes. La composition, les tables de routage et les contrôles sont définis une seule fois ici. Le plugin inclut le commit HVE Core exact épinglé par sa version source. Les dépôts MCP et MAF restent des intégrations d'hôte séparées, pas des dépendances du plugin.

hve-squad-mcp — le serveur MCP

github.com/Peter-N91/hve-squad-mcp · site de documentation

Le serveur expose des outils de haut niveau invocables par un modèle, qui correspondent aux intentions de routage de la squad plutôt qu'aux agents individuels : squad_research, squad_plan, squad_review, squad_architect, squad_run et squad_federate, ainsi qu'un outil déterministe de production de fichiers squad_render_pptx. Les entrées de chaque outil reprennent les arguments du prompt /squad.

Il fonctionne selon deux modes, à des niveaux de maturité différents :

  • Délégué (stdio) — VS Code délègue aux véritables agents déployés, ce qui reproduit le comportement du package complet. Leur installation est nécessaire.
  • Embarqué (Streamable HTTP distant + Entra) — accessible à des hôtes tels que Copilot Studio, ce mode résout les personas côté serveur à partir des agents inclus, avec authentification, contrôles, isolation des locataires et plafonds de coût. Le périmètre est consultatif : des livrables textuels finalisés, et non de l'implémentation ou du déploiement exécutant du code.

Lisez d'abord le tableau d'état. Le README et le site de documentation du serveur indiquent explicitement ce qui fonctionne aujourd'hui et les extensions d'exécution reportées. Fondez-vous sur ces sources, plutôt que sur cette page, pour connaître les capacités du mode distant.

Points d'entrée utiles sur son site : Bien démarrer, Outils, Configuration et Déploiement.

hve-squad — le plugin Copilot

Le plugin est généré depuis ce dépôt par scripts/Build-SquadPlugin.ps1. La publication manuelle écrit la version stable dans la branche plugin et la version de test dans plugin-preview. Chaque branche contient un seul marketplace et un seul plugin. 

copilot plugin marketplace add Peter-N91/hve-squad#plugin
copilot plugin install hve-squad@hve-squad

HVE Core est inclus, pas découvert à côté du plugin. L'arborescence générée copie chaque composant déclaré par le commit HVE Core exact épinglé dans apm.yml et consigne ce commit dans .github/plugin/hve-core-source.json. Une mise à jour normale actualise donc ensemble Squad et HVE Core. N'installez pas un second plugin hve-core.

Le plugin ne contient ni mcp.json ni .mcp.json. Installez hve-squad-mcp séparément uniquement lorsqu'un hôte MCP a besoin des outils sortants. Les instructions pour les versions stable, preview, les mises à jour et la solution de repli se trouvent dans Bien démarrer.

Comment les versions restent alignées

La publication du plugin reste manuelle. Le workflow sélectionne une référence stable immuable ou une référence preview glissante, récupère le commit HVE Core épinglé par cette référence, construit le plugin autonome et actualise la branche correspondante de ce dépôt. Une modification du contenu sans changement de version est refusée afin que les clients installés détectent les mises à jour. MCP et MAF conservent leurs propres processus de publication. Consultez Maintenance.
